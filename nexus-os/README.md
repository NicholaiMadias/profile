# Nexus OS Preview

The preview sends a prompt and optional context to your own Gemini backend. The
Chrome extension can copy selected text into the editable context field. It
sends text only when you submit the form. The website and extension use the same
client. The existing Nexus Assist package has its own companion and setup.

## Local setup

1. Set `GEMINI_API_KEY` and `NEXUS_ACCESS_TOKEN` in your environment. Use a
   random token of at least 32 characters, for example one generated by
   `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
2. From the extracted package, run `python backend/agent_server.py` with Python
   3.12. Check `http://127.0.0.1:8080/healthz`.
3. In Chrome, open `chrome://extensions`, turn on Developer mode, choose
   **Load unpacked**, and select the extracted `extension` folder.
4. Open the extension, enter `http://127.0.0.1:8080` and the access token, then
   submit a prompt. Approve the requested backend host permission.

## Cloud Run

Deploy the `backend` directory as a Cloud Run container. Inject
`GEMINI_API_KEY` and `NEXUS_ACCESS_TOKEN` from Secret Manager. Configure the
service to allow browser requests without a Google IAM login. The API checks
the Nexus bearer token on every prompt. Use a dedicated token and set Cloud Run
maximum instances and Gemini quota for your intended usage. The token grants
access to the Gemini quota attached to that service.

Enter the service's HTTPS `run.app` root URL in the web preview or extension.
The default browser origin is `https://nicholai.online`. For a trusted preview
or local web build, set `NEXUS_ALLOWED_ORIGINS` to the exact permitted origins,
comma-separated. For web use, the backend must permit the page's origin.
`GEMINI_MODEL` optionally overrides `gemini-2.5-flash`.

The browser keeps the Nexus token in the open form for the current session.
The backend sends the prompt and context to Gemini. Keep the Gemini key on
the server and share the Nexus token only with authorized users.
