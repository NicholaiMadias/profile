# Security audit and operational handoff (2026-11-23)

Scope: `NicholaiMadias/profile` source on the security branch. This is a source review and defensive hardening pass, **not** a penetration test, live Firebase rules deployment, or all-dependencies-clean certification.

## Remediated in source

- **Google Apps Script:** `public/Apps/pushToGitHUB.js` previously accepted requests with no `missionKey` and published a working fallback key string. New version requires a 32+ character `MISSION_KEY` Script Property and a matching key on **every** request, with a bounded request body and generic errors. No default key exists. Google Apps Script has versioned deployments; changing GitHub does **not** update an existing web app.
- **LMS API:** `backend/main.py` previously allowed unauthenticated profile reads, progress sync, credit top-ups and lesson writes by arbitrary user ID. Account operations now check a verified Firebase ID token and account ownership; credit top-ups require an `admin` custom claim; client-supplied credits are rejected. Blog writes require `editor` or `admin` custom claims. CORS defaults to localhost and can be set through `LMS_ALLOWED_ORIGINS`.
- **Firestore rules in source:** Public reads now require published posts; authors may access their drafts; writing posts requires an editor/admin custom claim. `FeaturedArticles` queries only published posts. `firestore.indexes.json` contains the composite index for the published-post query.
- **Deployment:** Vercel and Firebase Hosting source config now specify anti-framing, no-sniffing, referrer, permissions, HSTS, and a narrow CSP. X-Frame-Options is SAMEORIGIN because /admin embeds a same-origin test frame.
- **Supply chain:** The ESM npm audit script fails when an audit fails instead of swallowing errors. Dependabot covers nested npm and Python projects; CodeQL scanning and backend guard regression checks were added. Python LMS dependencies were upgraded from old pinned versions; compatibility still needs staging/runtime testing. `.gitignore` now excludes common local credentials.

## Required owner operations before claiming a secure production deployment

1. **Google Apps Script (highest priority):** Find any deployed webhook created from `public/Apps/pushToGitHUB.js`. Disable its old public deployment or publish a new version with the patched code. Remove the previously published fallback value from Script Properties; create a fresh random `MISSION_KEY` (at least 32 characters) through a secret manager. If a production token or GitHub API token was handled by an unprotected endpoint, rotate/revoke it in its provider. Restrict Apps Script access to approved accounts if feasible, instead of `Anyone`. Never put the new key in client-side JavaScript, a public file, or a commit.
2. **Shared Firebase project caution:** `.firebaserc` defaults to `amazing-grace-hl`. This may be shared with other websites/apps. **Do not run `firebase deploy --only firestore` using this repo's draft rules, and do not replace the live rules wholesale.** Merge the new `posts` restrictions into the *authoritative* shared project's rules only after checking every collection and executing the project's emulator tests. Create the composite index in the intended project first, and arrange custom `editor`/`admin` claims through a trusted admin procedure. Deploy, then verify both public reading and authorized edits. The updated `firestore.rules` and `firestore.indexes.json` are reference proposals only; `firebase.json` intentionally does **not** wire them for automatic deployment.
3. **GitHub Actions:** Resolve account billing lock at https://github.com/settings/billing and verify checks on `main`: website, endpoint Python/PowerShell, dependency audit, gitleaks, CodeQL and any E2E jobs. The existing Vercel build gate is **not** a substitute for these security checks.
4. **Repository administration:** Enable branch protection/rulesets on `main` with required reviewed PRs and required checks after CI is functional. Prefer restrictive Actions permissions and reviewed, SHA-pinned third-party Actions. Check GitHub secret scanning/security alerts and revoke any actual compromised credentials. No GitHub Actions runner or secret scan was available during this review.
5. **Runtime validation:** Test the Python API against unauthorized and authorized Firebase ID tokens, negative/oversized credit amounts, editor claims, CORS preflight, and cloud credentials. Test the Vercel preview, including login, same-origin frame, LMS, and static assets. Verify production headers after deployment. Newly pinned backend libraries need a staging smoke test.
6. **Companion downloads:** Source includes downloadable browser extensions/local command helpers and binary ZIP artifacts. Rebuild and audit distribution archives against reviewed source before asking users to run them; this audit did not inspect executable archive contents.

## Residual limitations

- Owner-owned progress/XP is still partially client-provided. It is **not** trustworthy for competitive rankings, payments, awards, or entitlements until validated by server-side game rules.
- Full repository git-history secret scanning, vulnerability scan, Python runtime integration tests, browser E2E, and live cloud security configuration checks cannot be certified while GitHub Actions is locked and deploy-owner access is not confirmed.
- Firebase `NEXT_PUBLIC_*` keys are public client configuration, not private provider secrets. Apply appropriate Firebase API restrictions in Google Cloud; never use these keys as standalone authorization.
- Do not close CI issue #52 until runners execute and required checks pass.
